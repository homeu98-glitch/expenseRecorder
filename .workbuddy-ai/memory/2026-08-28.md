## M10 POS 庫存表：macau-pos 內建庫存概念（commit 7133b69，已 push origin/main）
用戶需求：基於現有收據在 macau-pos 內新增庫存表功能（不僅收據，須有庫存概念），僅加至 macau-pos、不可加到 expense recorder。實作：
- `supabase/migrations/0013_inv_products.sql`：macau-pos Supabase 新增 `inv_products`（品名/品類/單位/current_qty/avg_unit_cost/last_purchase_date/last_supplier/reorder_level/note/updated_at trigger + `(store_id, lower(name))` unique index）+ `inv_stock_movements`（盤點稽核 cascade）。全部 idempotent。
- `src/lib/inventory-products.ts`（server-only）：CRUD + `adjustStock`（prev/new/delta/reason） + `syncFromReceipts`（依 expenseRecorder `user_id` 聚合 receipt_items.name → upsert）。
- 4 條 routes：`products` CRUD + `[id]/adjust` + `sync-from-receipts`（同時持有 macau client + expense client，解析 account→userId，呼叫 syncFromReceipts，回 summary）。
- `src/components/inventory/inventory-table.tsx`：庫存表 section，含 KPI（品項數/總值/低庫存數）+ 「從收據同步」/「新增庫存品」/品項卡（低庫存紅框、顯示品類/單位/current_qty/avg_unit_cost/最後採購/最後供應商/編輯/盤點/刪除）+ `ProductFormModal` + `StocktakeModal` + 刪除確認。
- `inventory-view.tsx`：加 `merchantId` 讀取、render `<InventoryTable merchantId={merchantId} account={account} />` 於供應商區塊後。

**設計**：sync 從 expenseRecorder 讀 `user_id` 的所有 receipts → 依 receipt_items.name 聚合：新品 `current_qty` = 累計採購量（一次性種子）、`avg_unit_cost` = 加權平均；既有品只更新 `avg_unit_cost` / `last_purchase_date` / `last_supplier` / `category`（`current_qty` 由盤點維護）。重跑冪等。低庫存 = `reorder_level > 0` 且 `current_qty < reorder_level`。所有 routes `eq("store_id", merchantId)` 店別隔離。expenseRecorder 完全不寫。

驗證：ESLint 7 檔 EXIT=0；tsc 僅剩預存 `layout.tsx` false-positive。`INTEGRATION_PLAN.md` §12.1 加 M9/M10 行 + 新 §12.9（兩者合併記錄）。

**待用戶**：macau-pos Supabase 執行 `supabase/migrations/0013_inv_products.sql` 建表；expenseRecorder 仍需 `supabase_schema.sql`（sync 來源）。

**⚠️ SQL 前置修正（M10 sync 實際依賴）**：M10 `syncFromReceipts` 在 `inventory-products.ts:193` 用 `merchants.eq("user_id", userId)` 過濾供應商，但 `expenseRecorder/supabase_schema.sql`（v1）建立的 `merchants` 表**沒有 `user_id` 欄**（只有 `id/name/address/created_at`）；同檔 `receipts` 則已有 `user_id`（NOT NULL）。故只跑 v1 時，M10 同步會因 `merchants.user_id` 不存在而 500。修法：跑完 v1 後，再單獨執行 v2 的 `ALTER TABLE merchants ADD COLUMN IF NOT EXISTS user_id UUID REFERENCES shop_users(id) ON DELETE CASCADE;`（即 `supabase_schema_v2.sql:41`），**勿**跑整份 v2（含 `TRUNCATE TABLE receipts/merchants/...` 會清掉資料＋重插測試店戶）。receipts 的 user_id 已由 v1 提供。
