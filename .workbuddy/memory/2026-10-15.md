## 修 503 upstream_unavailable（接 2026-10-14）

- 用戶在 SQL Editor 直接 `select ledger_purchase_report(...)` 捕獲到真實報錯：
  `ERROR: 42803: subquery uses ungrouped column "r.raw_ocr_data" from outer query`
  （PL/pgSQL function ledger_purchase_report line 114，即 items[] 聚合段）。
- **根因**：items 聚合嘅相關子查詢 `prev_avg` 比較
  `receipt_currency(r2…) = receipt_currency(r.raw_ocr_data, r.currency)`；
  外層 `g` 用 `group by it.name, receipt_currency(r.raw_ocr_data, r.currency)`，
  所以 `r.raw_ocr_data` **唔係 grouped column**，Postgres 禁止喺相關子查詢引用。
  v1 係 `group by it.name, r.currency`（r.currency 直接 grouped）所以無事；
  改寫版把 group by 換成函式表達式、但子查詢仲寫緊 raw 欄 ⇒ 42803。
- **修法**（`supabase_purchase_report_currency_fix_v1.sql` items 段）：
  下層加多一層 subquery `b`，先計 `receipt_currency(...) as eff_currency`，
  外層 `group by b.name, b.eff_currency`，子查詢改為
  `receipt_currency(r2…) = b.eff_currency`（b.eff_currency 已 grouped，合法）。
  全檔其餘 group by 點（kpi/daily/suppliers/payment/itemsTotal/receipts[]）都無相關子查詢，無同類問題。
- **點 apply**：SQL Editor 重跑成個 `supabase_purchase_report_currency_fix_v1.sql`（idempotent；
  A/B 回填段已 commit 會變 no-op，函數 create or replace 係真正修復；底嘅驗收 SELECT 會顯示現況）。
  跑完再打上游 → 應返 HTTP 200，`kpi.currencies = ["MOP","RMB"]`。
- 決策：寫入端已收口（POST/PATCH/save-receipt 同時寫頂層 + raw），`receipt_currency()` 改寫係防禦層；
  今次既修正咗改寫，兩者並存無衝突。SQL 係 server-side，唔使 deploy app 就改到 RPC。
